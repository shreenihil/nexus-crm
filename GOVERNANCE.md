# Governance Model

Nexus CRM is governed under a **Benevolent Dictator for Life (BDFL) with an Advisory Council** model, designed to ensure technical vision, rigorous security standards, and rapid development while giving a strong voice to community contributors and enterprise self-hosters.

## Leadership Structure

### 1. BDFL / Project Lead
- Sets overall technical and architectural direction.
- Has final decision authority on controversial pull requests or architectural disagreements.
- Responsible for maintaining open-source principles, Apache-2.0 licensing fidelity, and core project values.

### 2. Core Maintainers
- Active committers with write access to the repository.
- Responsible for daily triage, code review, issue management, and release engineering.
- Maintainers are nominated based on consistent, high-quality contributions across code, testing, documentation, or security audits.

### 3. Advisory Council
- Formed by community leaders, enterprise self-hosters, and key contributors.
- Meets quarterly to review roadmap priorities, discuss major Architectural Decision Records (ADRs), and address ecosystem needs.

## Decision-Making Process
1. **Minor Changes & Bugfixes**: Approved by any core maintainer via standard pull request review.
2. **Major Architectural Changes**: Proposed via an **Architectural Decision Record (ADR)** under `/docs/decisions/`. Open for community comment for a minimum of 7 calendar days before review and sign-off.
3. **Consensus Seeking**: The project strives for consensus. If consensus cannot be achieved, the BDFL makes the final determination.

## Becoming a Maintainer
Contributors who demonstrate technical proficiency, constructive community interactions, and commitment to the project over a period of 3-6 months may be nominated by existing maintainers.
